# RAG 知识库使用说明

> 面向日常使用者的操作手册：资料存哪里、删除会怎样、要不要重复喂、以及摄入/提问/备份/删除等常用命令。

---

## 1. 喂进去的资料存在哪里？

所有资料摄入后，统一存在**一个 SQLite 文件**里：

| 项目 | 值 |
|---|---|
| 默认位置 | `data/ragkb.sqlite` |
| 可配置 | 环境变量 `RAGKB_STORE_PATH`（`.env` 里改） |
| 文件性质 | 单个本地数据库文件，无需额外服务 |
| 是否进 git | 否（`data/` 已被 `.gitignore` 排除，不会提交到 GitHub） |

### 库里存了什么？不存什么？

| 存了 ✅ | 不存 ❌ |
|---|---|
| 每个文本块的内容（切好的小段文字） | 原始文件本身（PDF/源码/压缩包不会被复制进库） |
| 每块的向量（embedding，一串数字） | 原始二进制（.a/.bin/.wav 等） |
| 元信息：来源路径、页码、块序号、客户/型号标签 | — |

> 关键点：**原始文件和你喂进库里的数据是"两套东西"**。摄入时系统只是把文件"读一遍"、抽出文字+算向量后存进 SQLite；原始文件之后怎么动，都不影响库里已有的数据。

---

## 2. 删除会怎样？（你关心的重点）

分三种情况，结论完全不同：

| 你删的是 | 结果 |
|---|---|
| 原始文件（如 `D:\Code\AI\RAG_Test\5766\...`） | ✅ **不影响**。库里的文本块已经独立存在，问答照常 |
| 库文件 `data/ragkb.sqlite` | ❌ **全没了**。所有喂进去的资料一次性清空，必须重新 `ingest` |
| 某一份资料（单个来源） | 只删那一份。CLI `delete` 命令（推荐），或 API `DELETE /documents/{source}` |

### 删除单个来源（CLI，推荐）

```bash
# ① 先看库里有哪些来源（含各来源的块数）
.venv\Scripts\python -m apps.cli.main list

# ② 撤回某一份（填完整路径，或只填能唯一匹配的子串都行，如文件名）
.venv\Scripts\python -m apps.cli.main delete "D:\Code\AI\RAG_Test\5766\datasheet\错误文件.pdf"
# 或简写：.venv\Scripts\python -m apps.cli.main delete "错误文件.pdf"
# 输出：Deleted N chunks: D:\...\错误文件.pdf
```

### 删除单个来源（API）

```bash
# 先登录拿 token
TOKEN=$(curl -s -X POST http://127.0.0.1:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r .token)

# 列出当前库里有哪些资料（看 source 全路径）
curl -s http://127.0.0.1:8000/documents -H "Authorization: Bearer $TOKEN"

# 删除某一份（source 用 URL 编码后的完整路径）
curl -s -X DELETE "http://127.0.0.1:8000/documents/D%3A%5CCode%5CAI%5CRAG_Test%5C5766%5Cdatasheet%5Cab5766c_datasheet_v0.0.4.pdf" \
  -H "Authorization: Bearer $TOKEN"
```

> 想彻底清空重来：直接删 `data/ragkb.sqlite`（可选再删同目录的 `-wal`/`-shm` 文件），然后重新 `ingest`。

## 3. 喂一次就够了吗？

**够。** 一旦摄入完成，数据就持久化在 `data/ragkb.sqlite` 里，重启程序、关机都不会丢。

只有以下**三种情况**需要重新喂：

1. **删了库文件** `data/ragkb.sqlite`（见上表）。
2. **换了 embedding 模型**（向量维度变了，比如 768 维本地 BGE ↔ 1024 维 qwen3.7）：维度对不上会检索报错，**必须删库重建**。
3. **新增了文件、或某个文件内容更新了**：再跑一次 `ingest` 即可。

> 重复喂同一批文件**不会产生重复数据**——每块的 ID 由「来源+页码+序号」哈希生成，重复摄入走的是 `INSERT OR REPLACE`（覆盖式去重），是幂等的，放心反复喂。

## 4. 日常使用命令（CLI）

```bash
# 准备工作（Windows 直接用 .venv\Scripts\python 前缀，无需 activate）
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"   # Linux/macOS: source .venv/bin/activate
cp .env.example .env                               # 然后填 API key / 选 provider

# ① 摄入资料（喂一次）—— 目录或单个文件都行
.venv\Scripts\python -m apps.cli.main ingest "D:\Code\AI\RAG_Test\5766"
# 输出：Ingested 1097 chunks.

# ② 提问（会带引用来源）
.venv\Scripts\python -m apps.cli.main ask "AB5766C 的 CPU 是什么架构？"
.venv\Scripts\python -m apps.cli.main ask "如何初始化 GPIO？" -k 6   # 手动指定 top-K

# ③ 看库里有哪些资料 / 删除某一份（撤回错误文件）
.venv\Scripts\python -m apps.cli.main list
.venv\Scripts\python -m apps.cli.main delete "错误文件.pdf"   # 完整路径或唯一子串都行

# ④ 备份库文件（建议定期做）
.venv\Scripts\python -m apps.cli.main backup ./backups

# ⑤ 检索质量评估（可选）
.venv\Scripts\python -m apps.cli.main eval examples/eval_example.json

# ⑥ 启动 Web / API 服务
.venv\Scripts\python -m uvicorn apps.api.main:app --reload
# 浏览器打开 http://127.0.0.1:8000/ （默认账号 admin / admin123）
```

## 5. 通过 Web / API 操作

### 常用 API 一览

| 操作 | 方法 & 路径 | 说明 |
|---|---|---|
| 健康检查 | `GET /health` | 看服务状态、当前 provider 配置 |
| 登录 | `POST /auth/login` | 返回 JWT `token` |
| 上传/摄入 | `POST /ingest`（multipart） | 可带 `customer`/`model`/`category` 标签；`.zip` 自动解压 |
| 提问 | `POST /ask` | `{"question": "...", "category": "AB5766C"}` |
| 列出资料 | `GET /documents` | 看库里有哪些来源、各多少块；`?category=` 过滤 |
| 删除资料 | `DELETE /documents/{source}` | 删单个来源 |
| 整组删除 | `DELETE /documents/folder/{folder}` | 删某个文件夹/压缩包下的全部资料 |
| 分类管理 | `GET/POST /categories`、`PATCH/DELETE /categories/{name}` | 建/查/重命名/删分类 |
| 用户管理 | `POST /users` 等 | 建客户账号、配可见范围 |

### 上传并提问示例

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r .token)

# 上传（带客户/型号标签，用于权限隔离）
curl -F "file=@docs/guide.md" -F "customer=acme" -F "model=x1" \
  -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/ingest

# 提问
curl -X POST http://127.0.0.1:8000/ask \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question": "如何配置 GPIO 引脚？"}'
```

## 6. 多芯片分类与业务扩展

资料除了 `customer`/`model` 权限标签，还有 **`category`（分类）**，用于按「芯片型号 / 项目」整理。

- **两级结构**：业务域（如 `芯片SDK`、`嵌入式-ESP32`、`嵌入式-Linux`、`嵌入式-ROS`）→ 分类（如某颗芯片 `AB5766C`、`AB573X`、`BT897X`，或某个项目）。
- **加一颗新芯片** = 网页「分类管理」新建一个分类；**加一个新业务** = 新建一个业务域。**无需改代码**。
- **网页操作**（推荐）：登录后切到「分类管理」建分类；「资料管理」上传时选所属分类、按分类查看/删除；「问答」里可限定某个分类提问。
- **命令行回填**（一次性把现有 5766 资料归到 AB5766C，幂等）：
  ```bash
  .venv\Scripts\python scripts/seed_categories.py
  ```

分类相关的 API：`GET/POST /categories`、`PATCH /categories/{name}`（重命名，会同步改其下资料标签）、
`DELETE /categories/{name}`（删除分类并级联删除其下资料）。删除分类前会提示将删除的资料块数。

资料还有一个 **`folder`（文件夹）** 字段：目录摄入时取「被摄入根目录下的第一层子目录名」（如 `SDK代码`、`datasheet`、`sch`），
`.zip` 上传时取压缩包名。网页「资料管理」按文件夹分组展示，可折叠展开，并支持**整组删除**（一次删掉整个文件夹/压缩包）。
一次性把旧资料回填文件夹（幂等）：

```bash
.venv\Scripts\python scripts/backfill_folders.py
```

## 7. 常见问题（FAQ）

**Q：资料更新了，怎么刷新？**
再跑一次 `ingest` 该文件/目录即可（覆盖式去重，旧块会被新块替换）。

**Q：换了 embedding 模型后检索报维度错？**
因为向量维度变了。正确做法：备份旧库 → 删 `data/ragkb.sqlite` → 重新 `ingest`。

**Q：想看库里现在有哪些资料？**
CLI：`.venv\Scripts\python -m apps.cli.main list`；或 API `GET /documents`（需登录）。

**Q：怎么彻底删掉某一份资料（比如喂错了 PDF）？**
CLI 一行搞定：`.venv\Scripts\python -m apps.cli.main delete "错误文件.pdf"`（填完整路径或唯一子串都行）。也可以用 API `DELETE /documents/{source}`（source 需 URL 编码）。

**Q：原始文件能删掉省空间吗？**
能。喂完之后原始文件可以随意移动/删除，不影响已入库的数据。但建议保留一份，方便将来重新摄入或追溯。

**Q：部门又来了新芯片（或新项目），怎么加？**
网页「分类管理」新建一个分类即可（可选挂在某业务域下，如 `芯片SDK`）；上传资料时选该分类。加新业务同理，先建业务域（如 `嵌入式-ESP32`）再建其下分类。
